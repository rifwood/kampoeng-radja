## Form Pengumpulan Konten dan Aset Resmi — Fase 1 Landing Page Kampoeng Radja

Dokumen ini digunakan untuk mengumpulkan konten dan aset resmi dari pihak Kampoeng Radja sebelum digunakan pada website produksi.

> **Prinsip utama:**  
> Konten dan aset resmi yang diterima harus dapat dipetakan ke kebutuhan PRD dan Figma approved.
>
> Agent hanya menggunakan konten/aset sebagai **produksi resmi** setelah statusnya disetujui dan, untuk aset visual, sudah diverifikasi terhadap desain.

---

# 1. Cara Penggunaan

Gunakan satu baris untuk setiap item.

Tim perusahaan mengisi bagian yang ditandai:

```text
[PERLU DIISI]
```

Agent atau developer dapat membantu mengisi:

- referensi halaman;
- referensi section;
- referensi node/frame Figma;
- status implementasi;
- catatan teknis.

Konten yang belum disetujui tidak boleh dianggap sebagai data final perusahaan.

---

# 2. Status Konten / Aset

Gunakan status berikut:

| Status | Arti |
|---|---|
| `Belum diterima` | Konten/aset belum diberikan |
| `Diterima — belum diverifikasi` | Sudah diterima tetapi belum dicek |
| `Perlu revisi` | Ada masalah isi, kualitas, format, atau kesesuaian |
| `Disetujui` | Sudah disetujui untuk dipakai |
| `Produksi resmi` | Sudah disetujui dan digunakan sebagai asset/content produksi |
| `Tidak diperlukan` | Item tidak lagi digunakan pada scope final |

# 15. Aturan Penerimaan Aset Visual

Setiap aset visual resmi harus diperiksa:

- [ ] file dapat dibuka;
- [ ] kualitas cukup;
- [ ] hak pakai jelas;
- [ ] identitas asset benar;
- [ ] sesuai section yang dituju;
- [ ] dapat mengikuti aspect ratio/crop Figma;
- [ ] focal point sesuai;
- [ ] tidak blur pada viewport target;
- [ ] tidak memiliki watermark yang tidak seharusnya;
- [ ] status persetujuan jelas.

---

# 16. Validasi terhadap Figma

Sebelum aset resmi menggantikan `[FIGMA SEMENTARA]`, cek:

```text
Asset Produksi
      ↓
Section Figma
      ↓
Aspect Ratio
      ↓
Crop / Focal Point
      ↓
Visual QA
      ↓
Disetujui
```

Jika hasil aset resmi membuat desain berbeda signifikan:

> jangan langsung mengganti.

Catat kebutuhan review.

---

# 17. Aturan Konten Teks

Konten final harus:

- berasal dari perusahaan atau sumber yang disetujui;
- tidak mengandung fakta buatan agent;
- menggunakan ejaan/nama brand yang konsisten;
- mempertahankan informasi penting;
- dapat diedit minor untuk kebutuhan UI hanya jika tidak mengubah makna.

Jika teks terlalu panjang untuk layout Figma, jangan memotong fakta secara sembarangan.

Catat kebutuhan penyesuaian copy.

---

# 18. Aset Figma Selama Menunggu Konten Resmi

Jika aset produksi belum diterima tetapi Figma memiliki aset:

> gunakan `[FIGMA SEMENTARA]`.

Contoh pencatatan:

```text
Section: Home / News
Asset produksi: Belum diterima
Fallback: public/assets/figma/home/news-01.webp
Figma node: 123:456
Status: [FIGMA SEMENTARA]
```

Jangan menggunakan stock image sebagai pengganti jika aset Figma tersedia.

---

# 19. Hal yang Tidak Perlu Dikumpulkan

Jangan meminta konten/aset hanya karena pernah ada pada requirement lama.

Sebelum meminta ke perusahaan:

1. cek PRD terbaru;
2. cek Figma approved;
3. cek section yang masih aktif.

Jika section sudah dihapus dari desain/scope:

> ubah status menjadi `Tidak diperlukan`.

---

# 20. Checklist Handoff dari Perusahaan

Sebelum sebuah batch konten dianggap siap:

- [ ] file/link tersedia;
- [ ] nama item jelas;
- [ ] PIC persetujuan tercatat;
- [ ] status persetujuan tercatat;
- [ ] hak penggunaan media jelas;
- [ ] referensi halaman/section jelas;
- [ ] asset visual dapat dipetakan ke Figma;
- [ ] data personal memiliki izin jika diperlukan;
- [ ] tidak ada informasi yang masih ambigu.

---

# 21. Checklist Agent

Setelah menerima konten/aset:

- [ ] perbarui `CONTENT.md`;
- [ ] perbarui `ASSETS.md`;
- [ ] update status `[FIGMA SEMENTARA]` jika diganti;
- [ ] cek Figma mapping;
- [ ] verifikasi UI;
- [ ] catat blocker/revisi di `TODO.md`;
- [ ] jangan menghapus source asset sementara sebelum penggantian selesai diverifikasi.

---

# 22. Prinsip Akhir

> **Konten resmi menentukan fakta.**

> **Figma menentukan cara fakta dan aset tersebut ditampilkan secara visual.**

> **Agent tidak boleh mengarang fakta, mengganti aset seenaknya, atau menerima asset produksi tanpa memverifikasi dampaknya terhadap layout.**
